📐 Resource-Request Algorithm Steps

  1. 1
    Validate: Check Request[i] ≤ Need[i]. If false → error (process exceeded max claim).
  2. 2
    Check availability: Check Request[i] ≤ Available. If false → process must wait.
  3. 3
    Pretend to allocate: Temporarily update:
    Available = Available − Request[i]
    Allocation[i] = Allocation[i] + Request[i]
    Need[i] = Need[i] − Request[i]
  4. 4
    Safety check: Run the Safety Algorithm on the new state. If safe → grant request. Otherwise → rollback all changes.

📖 Banker's Algorithm — Theory

The Banker's Algorithm, developed by Edsger Dijkstra in 1965, is a deadlock avoidance algorithm. Like a banker who lends money only when they can still satisfy all customers' max needs, the OS grants resources only when it can guarantee a safe execution sequence exists.

✅

Safe State

A state where a sequence P1, P2, …, Pn exists such that each process can obtain resources, complete, and release for the next. All processes finish eventually.

⚠

Unsafe State

No safe sequence exists. The system may deadlock depending on future requests — but is not guaranteed to deadlock yet.

🔴

Deadlock

Every process in a set waits for a resource held by another process in that set — circular wait with no resolution.

Data Structures

nNumber of processes
mNumber of resource types
Available[j]Available instances of resource j
Allocation[i][j]Resources allocated to process i
Max[i][j]Maximum demand of process i
Need[i][j]= Max[i][j] − Allocation[i][j]

Safety Algorithm

  1. 1
    Initialize: Work = Available, Finish[i] = false for all i.
  2. 2
    Find: Process i where Finish[i] == false and Need[i] ≤ Work.
  3. 3
    Simulate: Work = Work + Allocation[i], set Finish[i] = true. Go to step 2.
  4. 4
    Conclude: If all Finish[i] == true → Safe. Else → Unsafe.

Resource-Request Algorithm

  1. 1
    If Request[i] > Need[i] → error (exceeds max claim).
  2. 2
    If Request[i] > Available → process must wait.
  3. 3
    Tentatively allocate: update Available, Allocation, Need.
  4. 4
    Run safety algorithm. If safe → grant. Else → rollback.

Key Properties

  • Every safe state is deadlock-free (but not vice versa).
  • Time complexity: O(n² × m) for the safety algorithm.
  • Requires processes to declare maximum resource usage in advance.
  • Can be overly conservative — may deny requests that would not cause deadlock.
  • Number of processes and resources must remain fixed.

✅ Advantages

  • Guarantees deadlock avoidance
  • Higher resource utilization than prevention
  • Safe sequence is deterministic
  • Well-studied and provably correct

⚠ Limitations

  • Requires advance declaration of max needs
  • May be overly conservative (false denials)
  • Fixed number of processes required
  • High overhead for very large systems
